# کارهای روزانه — پروژه اندروید کاملاً آفلاین

نام نمایشی برنامه: **کارهای روزانه**. نسخه منبع از فایل ZIP اصلی Google AI Studio استخراج شده و همان اجزای React، رنگ‌ها، چیدمان RTL و موشن‌ها را حفظ می‌کند. داخل نسخه APK، فایل‌های React/CSS/فونت در دارایی‌های محلی بسته‌بندی می‌شوند و از سرور اجرا نمی‌شوند.

> **این ZIP یک پروژه اندروید آمادهٔ ساخت است، نه فایل APK ساخته‌شده.** در محیط تهیه این بسته Android SDK، Gradle و بسته‌های npm لازم برای کامپایل وجود نداشتند. بنابراین کامپایل، نصب روی گوشی و تست پذیرش End-to-End انجام نشده و «بدون نقص» قابل تأیید نیست.

## امکانات پیاده‌شده در سورس

- اجرای UI از فایل‌های داخل APK؛ بدون دسترسی اینترنت (مجوز INTERNET در Manifest وجود ندارد و WebView درخواست‌های خارج از دارایی‌های داخلی را مسدود می‌کند).
- ذخیره کارهای فعال، آرشیو انجام‌شده‌ها و تم به صورت محلی در اپ. داده‌های ویجت در SharedPreferences محلی ذخیره می‌شوند؛ نیازی به حساب کاربری یا سرور نیست.
- ویجت بومی صفحه اصلی: نمایش کارها، رنگ اولویت، پیش/پس‌رفتن بین روزهای شمسی، تکمیل کار با لمس ردیف، بازکردن اپ و بازکردن فرم افزودن کار با دکمه +.
- انتخاب حالت روشن/تیره/AMOLED/شیشه‌ای/متریال و شفافیت از صفحه پیش‌نمایش ویجت؛ این تنظیمات به ویجت بومی ارسال می‌شوند.
- واردکردن تقویم باد صبا از **فایل محلی ICS یا متن آن**، بدون سرور. همگام‌سازی زنده از لینک اینترنتی در نسخه آفلاین غیرفعال است (بدون اینترنت ممکن نیست).
- نام برنامه، عنوان WebView، فایل Manifest وب، برچسب ویجت: **کارهای روزانه**.

## محدودیت‌های فنیِ مهم

- **ظاهر ویجت بومی صددرصد پیکسلی مشابه پیش‌نمایش React نیست.** Android Launcher از RemoteViews استفاده می‌کند و موشن‌ها و قابلیت‌های صفحه پیش‌نمایش (مثل جابه‌جایی Drag & Drop داخل پیش‌نمایش) را به همان شکل پشتیبانی نمی‌کند. طراحی، رنگ اولویت و تم تا حد ممکن هماهنگ شده است.
- فونت اصلی از Google Fonts به صورت آنلاین بارگذاری می‌شد؛ برای قطع کامل وابستگی به اینترنت، نسخه محلی **Noto Sans Arabic** به جای Vazirmatn قرار داده شده است؛ در نتیجه ممکن است برخی ابعاد متنی کمی متفاوت شوند. مجوز SIL OFL فونت در `THIRD_PARTY_FONT_LICENSE.txt` آمده است.
- آزمایش واقعی روی دستگاه انجام نشده؛ سازگاری و ثبات عملکرد هنوز باید با APK ساخته‌شده آزموده شوند.
- حداقل نسخه اندروید: **۷٫۰ (API 24)**. اپ بر WebView سیستمی اندروید متکی است ولی به نصب مرورگر یا اپ جانبی نیاز ندارد.
- پاک‌کردن داده‌ها یا حذف اپ موجب حذف داده‌های محلی می‌شود؛ قابلیت پشتیبان‌گیری فایل هنوز به برنامه افزوده نشده است.

## ساخت APK روی ویندوز

**پیش‌نیازهای کامپیوتر سازنده فایل** (نه گوشی): Node.js 22+، Java 17، Android Studio/Android SDK Platform 35 و Gradle 8.9. Android Studio هنگام Sync وابستگی‌های ساخت را دانلود می‌کند.

1. ZIP را در پوشه‌ای مانند `D:\Karhaye-Roozane` استخراج کنید.
2. در صورت نصب پیش‌نیازها، فایل `build-apk.bat` را اجرا کنید.
3. خروجی در مسیر `app\build\outputs\apk\debug\app-debug.apk` ایجاد می‌شود.
4. فایل APK را به گوشی انتقال دهید و نصب کنید. برای انتشار عمومی باید Release APK با کلید اختصاصی امضا شود.

**راه ساخت بدون Android Studio محلی:** همین پروژه را داخل یک مخزن GitHub قرار دهید و از Actions، جریان `Build Karhaye Roozane APK` را با `Run workflow` اجرا کنید. پس از موفقیت، Artifact با نام `karhaye-roozane-debug-apk` حاوی فایل APK است.

## چک‌لیست تست پذیرش روی گوشی

۱. نصب و بازشدن اپ با حالت هواپیما؛ ۲. تست ثبت، ویرایش، اولویت‌بندی و جابه‌جایی کارها؛ ۳. بستن کامل و بازگشایی برای تأیید نگهداری داده؛ ۴. افزودن ویجت از بخش Widgets اندروید؛ ۵. تغییر تم و شفافیت در برنامه و بررسی ویجت؛ ۶. تکمیل کار از ویجت و بررسی حضورش در آرشیو؛ ۷. دکمه + ویجت و ایجاد کار؛ ۸. جابه‌جایی روز در ویجت؛ ۹. تغییر اندازه ویجت؛ ۱۰. ورود یک فایل ICS محلی با اینترنت خاموش؛ ۱۱. آزمایش RTL، فونت و اندازه در حالت روشن و تیره، روی دستگاه واقعی.

## گزارش بررسی در محیط تهیه بسته

| بررسی | نتیجه |
|---|---|
| ساختار فایل‌های XML اندروید | PASS (پارسر XML) |
| نحو Java | PASS (Javac parser؛ بدون Resolve وابستگی‌های SDK) |
| نحو TypeScript/TSX | PASS (TypeScript transpiler؛ بدون Resolve وابستگی‌های npm) |
| وجود مجوز اینترنت | ندارد |
| ارجاع به فونت آنلاین در HTML نسخه آفلاین | ندارد |
| بیلد Vite | NOT RUN — بسته‌های npm در دسترس نبود |
| بیلد Gradle / APK | NOT RUN — Android SDK/Gradle در دسترس نبود |
| نصب/تست روی گوشی، ویجت و انطباق بصری | NOT RUN — دستگاه تست موجود نبود |

این گزارش «آماده برای کامپایل» است، نه گواهی سلامت یک APK ساخته‌شده.
